= Lti::Advantage RDoc Overview

The +lti-advantage+ gem implements the core parts of the
IMS Learning Tools Interoperability (LTI) 1.3 launch flow for Ruby tools.

== Implemented Core Flow

1. Parse and validate OIDC login initiation parameters.
2. Build an OIDC authentication request URL for platform redirect.
3. Validate the returned signed +id_token+ launch message.
4. Expose launch claims through a convenient value object.

== Main Entry Point

Use +Lti::Advantage::Client+ as the high-level API.

  require "lti/advantage"

  registration = Lti::Advantage::Registration.new(
    issuer: "https://platform.example",
    client_id: "client-123",
    authorization_endpoint: "https://platform.example/oidc/auth",
    jwks_url: "https://platform.example/.well-known/jwks.json",
    deployment_ids: ["deployment-123"]
  )

  client = Lti::Advantage::Client.new(registrations: [registration])

== Login Initiation Endpoint (Tool)

When the platform initiates login, build the auth request URL:

  request = client.authentication_request(
    login_params: params,
    redirect_uri: "https://tool.example/lti/launch"
  )

  redirect_to request.url

This step stores one-time +state+ and +nonce+ values for replay protection.

== Launch Endpoint (Tool)

When the platform posts +id_token+ and +state+ back to your tool:

  launch = client.validate_launch!(
    id_token: params.fetch("id_token"),
    state: params.fetch("state")
  )

  launch.message_type    # => "LtiResourceLinkRequest"
  launch.deployment_id   # => "deployment-123"
  launch.resource_link_id
  launch.roles

== Security and Validation Notes

The validator enforces:

* JWT signature validation against platform JWKS
* OIDC issuer, audience, +iat+, and +exp+ checks
* Required LTI 1.3 resource link claims
* Deployment and target-link consistency checks
* +state+ and +nonce+ single-use replay protection
* +nonce+ binding to the original +state+

== Extension Points

The client constructor accepts injectable components so you can adapt it to
your infrastructure:

* Custom state/nonce stores (for distributed environments)
* Custom JWKS repository and transport behavior
* Custom random token generators for testing
